# PRD：会員限定メディアサイト（ログイン／ペイウォール版）

**作成日：** 2026年7月23日
**ステータス：** 確定
**対象：** PHP基礎課題（セッション／ログイン回）
**ベース：** `PRD_DB.md`（会員登録DB版）＋ `PRD_CRUD.md`（更新・削除）に、ログイン機能を追加
**参考イメージ：** Courrier Japan などの「途中まで読めて、続きは会員登録／ログイン」型メディア

---

## 1. 概要

既存の会員登録システム（登録→メール認証→本登録）に、**ログイン・ログアウト**と**アクセス制限**を追加する。
サイトを「**会員限定メディア**」に見立て、記事は**途中まで誰でも読めるが、続きはぼかし（フェード）で隠れ、読むには会員登録／ログインが必要**にする（ペイウォール）。
さらに、ログインした会員だけが使える**マイページ**を用意し、自分の名前を変更できるようにする。

---

## 2. 目的

- 授業で習った **セッション（`$_SESSION` / `session_id`）** を実践的に習得する
- **ログイン・ログアウト**と、ログイン状態による**アクセス制限**を実装する
- 「誰でも見られる画面」と「ログイン会員だけの画面」を切り分ける設計を体験する
- 既存の会員登録システムを、実際のWebサービスに近い形へ発展させる

## 5. ペイウォールの仕様（今回の目玉）

記事詳細（`article.php`）は、**ログイン状態によって本文の見せ方を変える**。

| 状態 | 記事本文の見え方 |
|------|----------------|
| **未ログイン** | 冒頭**2〜3行だけ**表示 → その下がだんだん薄くなって読めなくなる（フェード）→「続きを読むには会員登録／ログイン」の案内を表示 |

> **無料で読める量：冒頭2〜3行（案A）** — しっかり課金誘導する Courrier に近い見せ方。
| **ログイン済み** | 全文をそのまま表示 |

### 実現方法（イメージ）

- 記事本文は「無料で見せる冒頭」と「続き」に分けて持つ（配列で `intro` と `body` に分割、または本文を途中で切る）。
- 未ログイン時：
  - `intro`（冒頭）だけ表示
  - その下端に **半透明の白グラデーション**を重ねて、文字がフェードアウトして見える演出（CSSで実現）
  - 続きは出力しない（＝HTMLソースを見ても続きは読めない ＝ ちゃんとした制限）
  - 「続きを読む」の案内ボックスを表示：
    - **会員登録＝primaryボタン（塗りつぶし・目立つ）** → `index.php`（会員登録）
    - **ログイン＝secondaryボタン（控えめ）** → `login.php`
    - 理由：来訪者の多くは新規のため、一番押してほしい会員登録を目立たせる（Courrier方式）
- ログイン時：`intro` ＋ `body`（続き）を全部表示

> ポイント：見た目だけ隠す（CSSで隠すだけ）のではなく、**未ログインには続きのHTML自体を出力しない**。そうしないと「ソースを見れば読めてしまう」ため。

## 6. 処理フロー

### ログイン

```
[login.php]
メールアドレス・パスワードを入力してPOST送信
        ↓
[login_act.php]
① session_start()
② POSTでメール・パスワードを受け取る
③ DBに接続（PDO）
④ SELECTで「メール一致・パスワード一致・status=active・deleted_at IS NULL」の会員を探す
        ↓
   見つかった？
   ├─ No  → 「ログイン情報が違います」＋ login.php へのリンク表示
   └─ Yes → $_SESSION を初期化し、session_id・user_id・name を保存
            → 「元の記事」があればその記事へ、なければ top.php へリダイレクト
```

### ログイン後の戻り先（決定事項）

- **ログイン経由**：読もうとしていた記事に戻す。
  - 記事ページの「ログイン」ボタンに記事id を付けて渡す（例：`login.php?back=3`）。
  - `login_act.php` はログイン成功後、`back` があれば `article.php?id=3` へ、なければ `top.php` へ。
- **会員登録経由**：登録は「入力→確認→メール→認証→完了」と長いため、元記事へは戻さず**通常フロー**（完了→ログイン→記事）とする。

### すでにログイン済みの人が login.php を開いたら（決定事項）

- `login.php` の冒頭でログイン済みかを確認し、**ログイン済みなら top.php へリダイレクト**する（ログイン画面は見せない）。

### アクセス制限（マイページ）

```
[mypage.php] 冒頭
① session_start()
② functions.php を読み込む
③ check_login() を実行
     ├─ 未ログイン → login.php へ強制移動（exit）
     └─ ログイン済 → session_id を再生成して $_SESSION を最新化 → 画面表示
```

### ログアウト

```
[logout.php]
① session_start()
② $_SESSION = array();（変数を空に）
③ Cookieのセッションを無効化（setcookieで期限切れに）
④ session_destroy();（セッション領域を破棄）
⑤ top.php へリダイレクト
```

### 名前変更（マイページ）

```
[mypage.php] 名前の入力フォーム（自分のidはセッションのuser_idを使う）
        ↓ POST
[mypage_update.php]
① session_start() ＋ check_login()
② 新しい名前を受け取る
③ UPDATE users SET name=:name, updated_at=now() WHERE id=:id
   （id は $_SESSION['user_id'] を使う ＝ 他人の情報は変更できない）
④ $_SESSION['name'] も新しい名前に更新
⑤ mypage.php へリダイレクト
```

## 7. ログイン判定関数（functions.php）

授業の `check_session_id()` を、この課題向けに `check_login()` として用意する。

- **未ログインとみなす条件**：`$_SESSION['session_id']` が無い／`session_id()` と一致しない
- **未ログイン時**：`login.php` へリダイレクトして `exit`
- **ログイン時**：`session_regenerate_id(true)` で id を作り直し、`$_SESSION['session_id']` を最新に保つ

また、記事のペイウォール判定用に「ログインしているか（true/false）」を返す小さな関数（例：`is_login()`）も用意する。
（`mypage.php` は追い返す `check_login()`、`article.php` は見せ方を変えるだけの `is_login()` を使い分ける）

## 8. DB / テーブル設計

**変更なし（`ALTER TABLE` 不要）。** ログインに必要な列は既存の `users` テーブルにそろっている。

| 使う列 | 用途 |
|--------|------|
| `email` / `password` | ログイン照合 |
| `status` | `active`（本登録済み）だけログイン許可 |
| `deleted_at` | `NULL`（退会していない）だけログイン許可 |
| `id` / `name` | マイページ表示・名前更新 |

---

## 9. SQL設計

### ログイン照合（SELECT）— `login_act.php`

```sql
SELECT * FROM users
WHERE email = :email
  AND password = :password
  AND status = 'active'
  AND deleted_at IS NULL;
```

- パスワードは今回**平文のまま照合**（授業サンプルに合わせる。ハッシュ化はスコープ外）
- 入力値は必ずバインド変数（`:email`, `:password`）で渡す（SQLインジェクション対策）

### 名前更新（UPDATE）— `mypage_update.php`

```sql
UPDATE users SET name = :name, updated_at = now() WHERE id = :id;
```

- 【重要】`WHERE id = :id` を必ず付ける。`:id` は `$_SESSION['user_id']` を使う（他人を書き換えない）

## 10. セッションの使い方

| タイミング | 処理 |
|-----------|------|
| ログイン成功（`login_act.php`） | `$_SESSION` を初期化し、`session_id` / `user_id` / `name` を保存 |
| 保護ページ表示時（`mypage.php` など） | `check_login()` で判定＋`session_id` を再生成して最新化 |
| 記事表示時（`article.php`） | `is_login()` でログイン有無を確認し、本文の出し方を分岐 |
| ログアウト（`logout.php`） | `$_SESSION=array()` → Cookie無効化 → `session_destroy()` |

### セッションに保存する値

| キー | 中身 | 用途 |
|------|------|------|
| `session_id` | 現在のセッションID | ログイン判定（毎回最新に更新） |
| `user_id` | 会員のid | 名前更新のWHEREに使う |
| `name` | 会員の名前 | 画面に「◯◯さん」と表示 |

## 11. 記事データ（articles.php）

DBは使わず、PHPの配列でダミー記事を3件用意する。

```php
$articles = [
  1 => [
    'title' => '...',
    'intro' => '無料で読める冒頭2〜3行...',
    'body'  => 'ログイン後に読める続き（3〜4段落）...',
  ],
  // 2, 3
];
```

- `top.php` … `title` と `intro` の一部を一覧表示
- `article.php` … URLの `?id=` で該当記事を選び、ログイン状態で `body` を出し分け

### 収録する記事（確定・3本）

| id | タイトル | 冒頭（無料・2〜3行） |
|----|---------|--------------------|
| 1 | 時間はあったのに、なぜ人は“ギリギリ”で動くのか | 締め切りまで2週間あったはずなのに、気づけば前日の深夜。誰もが身に覚えのあるこの現象、実は「怠け」ではなく、脳のある“クセ”が関係していた—— |
| 2 | AIに頼るほど、人は“決められなく”なる？ | 調べ物も要約もAIにお任せ。便利になった一方で、「自分で決められない人が増えている」という声が。AIは私たちの頭を良くするのか、それとも—— |
| 3 | 夏休み＝お弁当地獄。働く親のリアル攻略法 | 子どもの夏休みは楽しい。でも親にとっては、毎日のお弁当と仕事が重なる“最も過酷な40日間”でもある。先輩たちはどう乗り切ってきたのか—— |

- 続き（`body`）は各記事3〜4段落の読み物ダミーを実装時に用意する。

## 14. スコープ外（今回はやらない）

- パスワードのハッシュ化（`password_hash()` / `password_verify()`）※平文のまま
- 管理者／一般ユーザーの権限分け（is_admin）
- 記事のDB化・記事投稿機能
- 「読んだ記事数の上限（月◯本まで無料）」のような高度なペイウォール
- ソーシャルログイン等
