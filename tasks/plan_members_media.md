# 設計図：会員限定メディアサイト（セッション／ログインの課題）

**作成日：2026-07-23**
授業で習った「セッション」「ログイン・ログアウト」「アクセス制限」を、今の会員登録システムに乗せる。
テーマは「**記事を読むには会員登録・ログインが必要なメディアサイト**」。

> この段階では **まだコードは書かない**。何を・どの順で作るかを決めるための設計図。
> ※ 最新の確定仕様は `PRD_LOGIN.md` を正とする（この設計図はそれに合わせて更新済み）。

---

## 0. 作りたいもの（ひとことで）

TOPに記事の一覧が並ぶ。記事は**誰でも開けて途中まで読める**が、続きは薄くなって消える（ペイウォール）。
続きを読むには会員登録・ログインが必要。ログインすれば全文が読める。マイページで自分の名前を変えられる。

---

## 1. 画面の流れ（全体像）

```
[top.php] TOPページ（記事一覧・ダミー）… 誰でも見られる
   │  記事の「読む」をクリック（?id=●）
   ↓
[article.php] 記事詳細 … 【誰でも入れる（追い返さない）】
   ├─ 未ログイン → 冒頭2〜3行だけ表示 → 続きはフェードで消える
   │                └─「続きを読むには 会員登録 / ログイン」ボタン → login.php / index.php
   └─ ログイン済 → 記事を全文表示
                 │
                 ├─ ヘッダーに「マイページ」「ログアウト」リンク
                 ↓
            [mypage.php] 自分の名前を変更できる 【ログイン必須：未ログインは login.php へ追い返す】
```

- **誰でも見られる**：top.php、article.php（冒頭まで）、login.php、（会員登録の一連＝index.php〜complete.php）
- **ログインした人だけ**：article.php の続き本文、mypage.php
- ★記事は「追い返す」のではなく「見せ方を変える」。追い返すのはマイページだけ。

## 3. 授業で習ったことの対応（どこで何を使うか）

| 授業で習ったこと | この課題での使いどころ |
|---|---|
| `session_start()` | ログイン関連の全ページの先頭で宣言 |
| `$_SESSION` に保存 | ログイン成功時に「誰がログイン中か」を保存 |
| `session_id()` / 再生成 | ログイン判定のたびに最新のidに更新 |
| `check_session_id()` 相当 | `mypage.php` の先頭で実行し、未ログインなら login.php へ追い返す |
| ログイン有無の判定（is_login） | `article.php` で使い、続き本文を出すか／フェード＋ボタンにするかを分岐（追い返さない） |
| ログイン処理 | `login_act.php`（DBに一致する会員がいるか確認） |
| ログアウト処理 | `logout.php`（セッション変数・Cookie・セッション領域を破棄） |

## 4. ログインの仕組み（決めたこと）

- **ログインに使う情報**：メールアドレス ＋ パスワード
- **ログインを許可する条件**（DBで確認する3点）：
  1. メールとパスワードが一致する
  2. `status = 'active'`（＝メール認証まで済んだ本登録会員だけ）
  3. `deleted_at IS NULL`（＝退会していない）
- **セッションに保存するもの**（授業の書き方に合わせる）：
  - `session_id`（ログイン判定用・毎回最新に更新）
  - `user_id`（どの会員か）
  - `name`（画面に「◯◯さん」と出す用）

## 6. 確認しておきたいこと（実装前の決めごと）

1. **パスワードの扱い**
   - 今はパスワードが「そのままの文字」でDBに保存されている（授業のサンプルも同じ方式）。
   - 課題としては **今のまま（そのまま照合）でOK**。授業内容に忠実。
   - 余裕があれば「暗号化して保存（`password_hash`）」に改良できるが、**今回はやらない**想定。
2. **記事はダミーでOK**（DBに入れず、`articles.php` に配列で3〜5件用意）。
3. **一覧の中身は誰まで見せる？**
   - 案：TOPは「タイトルと冒頭だけ」誰でも見える → 続き（本文）は要ログイン。
   - （シンプルにするなら「タイトル一覧だけ表示、クリックで要ログイン」でも可）

## 8. 完成時の動作チェック（この通りになればOK）

- [ ] 未ログインで `article.php` を直接開く → login.php に飛ばされる
- [ ] 存在しないメール／パスワードでログイン → 失敗メッセージ＋やり直しリンク
- [ ] 本登録済み会員でログイン → 記事が読める
- [ ] 仮登録（status=pending）ではログインできない
- [ ] マイページで名前を変更 → DBに反映され、画面表示も変わる
- [ ] ログアウト後、`article.php` / `mypage.php` に入れない（login.phpへ）
- [ ] デバッグ用の一時コードを消したか

## 9. 用語（かんたん言い換え）

| 用語 | かんたんに言うと |
|---|---|
| セッション | サーバ側に「今ログイン中の人」を覚えておく仕組み |
| セッション変数（$_SESSION） | その覚えておく箱。どのページからでも中身を見られる |
| アクセス制限 | ログインしてない人をページに入れないこと |
| 論理削除（deleted_at） | 退会＝データは残すが「退会済みの印」を付ける |
| status(active/pending) | active=本登録済み / pending=メール認証まだ（仮登録） |
